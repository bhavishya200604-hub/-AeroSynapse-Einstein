# Architecture

Generated by `python scripts/make_architecture.py` (overview + code-derived module index).

## Layers and data flow

```
            ┌──────────────────────── Layer F: Workbench (ui/) ── CLI (cli.py) ────────────────────────┐
            │  Physics │ Simulation │ ML │ Optimization │ Research   ── call only the public API ───────│
            └───────────────────────────────────────┬──────────────────────────────────────────────────┘
                                                    │ experiments/runner.py (define→simulate→train→validate→optimise→report)
  Layer A  physics/        PDEProblem, Parameter, BCs, library (exact solutions), regime guards, airfoils
     │ problem objects
  Layer B  numerics/       FD / FV / FEM / NS-MAC / boundary layer / panel solvers + verification tools
     │ reference fields, datasets (ml/datasets.py), trusted evaluations
  Layer C  ml/  uq/        PINNs, samplers, FNO, DeepONet, POD/CNN/MLP, hybrids, AirfRANS loader; GP, ensembles, MC, Sobol
     │ predictions + uncertainty
  Layer E  validation/     metrics (vs independent references), trust policy + fallback, resource estimator
     │ accept / fall back to Layer B
  Layer D  optim/          design space, recorded problems, 11 optimisers, KKT, robust, 12-step protocol, inverse
     │ final candidate → re-evaluated by Layer B (trusted solver) → ACCEPT / REJECT
  Cross-cutting: config.py (pydantic YAML), experiments/record.py (Section-13 records), registry.py (plugins),
                 exceptions.py, safety.py (validation ladder + banner), device.py, logging_utils.py
```

## Key interfaces
* `PDEProblem` (physics/problem.py) is the single problem description consumed by solvers and PINNs.
* Solvers return arrays + diagnostics and **raise** (`SolverDivergenceError`, `StabilityError`, `RegimeError`)
  instead of returning plausible-looking invalid fields.
* `OptimizationProblem.evaluate(z)` is the only way an optimiser touches a model: every call is recorded with
  feasibility, uncertainty and source, and the budget is enforced.
* `OptimizationStudy.run(method, baseline_method)` enforces the 12-step protocol; the final design is
  re-evaluated by the trusted solver.
* `TrustPolicy.decide(...)` → `Decision(use_surrogate, reasons, checks)`; `guarded_predict` falls back automatically.
* `ExperimentRun(record)` writes `results/<id>/{record.json, config.yaml, metrics.json, history.csv, git_hash.txt}`;
  the hypothesis is written before the run starts.
* Registries `PHYSICS`, `SOLVERS`, `MODELS`, `OPTIMIZERS` (registry.py) let new components be added without
  editing core code (see guides/adding_a_physics_module.md).

## Evidence pipeline
`scripts/run_phase*.py` → `results/` → `scripts/make_report.py` (tables), `scripts/make_figures.py` (figures A–G),
`scripts/make_reproducibility.py` → `scripts/audit_claims.py` (every number in docs/paper must match an artifact;
negative-control tested) → `scripts/run_quality_gate.py` (tests, coverage, ruff, mypy). `scripts/reproduce_all.py`
runs the whole chain.
